# Troubleshooting the local demo

| Symptom                                              | What to check / recover                                                                                                                                                                                                                                                                                                                                        |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Databricks authentication missing or SQL unavailable | Confirm the designated host/warehouse/table and server-only CLI profile. Reauthorize with the documented `databricks auth login`; ensure the CLI is on the server PATH. Production mode cannot use CLI token lookup. Inspect safe HTTP/status messages; never print tokens or `.env`. Warehouse permissions/startup/network failures have no fixture fallback. |
| Canonical timeout / changed revision                 | Refresh canonical state; a timeout may have committed. Hospital/review requests recover with the same request UUID. Do not replay arbitrary writes or overwrite a newer revision. Duplicate canonical IDs require administrative repair.                                                                                                                       |
| Empty KB / waiting for reviewed evidence             | Distinguish absent/disabled pointer from a valid empty published release. Latest receipt had zero approvals. A designated human must review exact versions and explicitly publish the canonical candidate set. Local exports are not connected substitutes.                                                                                                    |
| Reviewer denied or stale preview                     | Check dedicated reviewer role, registry, allowlist and publish privilege. Refresh after canonical changes; decisions pin item version/hash and release previews pin fingerprint. Do not reuse approval for changed versions.                                                                                                                                   |
| Profile unconfirmed or superseded                    | Select current profile, wait for queue/worker, inspect suggestions and confirm as doctor. Edits, unlink or new snapshot invalidate old inputs. Hosting/validation failure is explicit; never add external fallback.                                                                                                                                            |
| `model_hosting_unverified`                           | Check live readiness, approved endpoint/entity/workload, single hosted entity and stable config. An endpoint URL alone is insufficient. Use token-safe metadata checker only when authorized; do not relax the guard.                                                                                                                                          |
| Stale matching package                               | Rematch against current confirmed profile/snapshot and unchanged active release. Historical packages without v1 are invalid. Worker cadence cannot make stale input current.                                                                                                                                                                                   |
| Invalid citations/content                            | Inspect claim/source membership and exact reviewed statements. Non-unknown funding/status disclosures require exact reviewed claims. Correct/enrich candidate, obtain real review and release anew; do not bypass the gate or merely add citation markers.                                                                                                     |
| Preview exists but library empty                     | Current worker publishes only with send-ready config, matching verified recipient and active subscription. Preview is intentionally not a canonical newsletter publication.                                                                                                                                                                                    |
| Email preview only                                   | Check mode/enabled flag, server recipient registry and canonical version, actual verification/authorization, subscription, Gmail secrets and HTTPS `APP_ORIGIN`. `.invalid` recipients cannot send. Test mode sends real email.                                                                                                                                |
| Gmail OAuth failure                                  | Confirm Google client/API settings, authorized sender/test-user policy, loopback redirect `http://127.0.0.1:8484/oauth/gmail`, send/read scopes and unoccupied callback port. Load both private env files in app/workers; never paste token responses.                                                                                                         |
| Gmail outcome `unknown`                              | Do not resend automatically. Worker performs bounded sent-mail Message-ID reconciliation; no search hit is not proof the message was unsent. Operator must resolve uncertainty without creating duplicate content.                                                                                                                                             |
| Gmail accepted but no delivery                       | Inspect actual authorized recipient inbox/spam. Acceptance and sender history are not receipt. Notification/report pipeline requires separate setup and actual evidence; reading is never a worker completion gate.                                                                                                                                            |
| Notification `setup_required` / quarantined          | Optional `email_mailbox/gmail`, topic/watch, Google-signed public push and configured audience/subscription/service identity are missing or invalid. Expired history/checkpoint requires operator resync; raw DSNs are reviewed, not trusted automatically.                                                                                                    |
| Local HTTP/HTTPS error or origin denied              | Preview supports `http://localhost:8081`. Send requires operator-provided HTTPS proxy/tunnel, exact `APP_ORIGIN` and sign-in there. No bundled HTTPS setup was verified. Do not disable origin/security checks. Secure cookies require HTTPS.                                                                                                                  |
| Queued work never runs                               | Start common runner with the same server env/account registry as app. It sleeps 30 seconds after all workers; inference/SQL can lengthen a loop. `unavailable` means canonical service failed, not idle success. Abandoned leases expire, not instantly clear.                                                                                                 |
| Document size/queue limit                            | The doctor document cap is 2 MB; history needs coordinated archival rather than deleting audit. SQL directory/response and Gmail event/report caps also fail visibly.                                                                                                                                                                                          |
| Port 8081 busy                                       | Reuse/identify the existing local server; strict-port intentionally refuses another port. Never kill another chat's process just to follow setup.                                                                                                                                                                                                              |

See [platform](../architecture/databricks-platform.md), [email](../architecture/email-delivery.md) and each component README for safe failure states and ownership. Historical Supabase migration/credential instructions do not repair the active runtime.
